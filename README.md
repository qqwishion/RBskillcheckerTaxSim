# Drag assistant для Windows / Roblox

Программа анализирует экран и отправляет W/E и клики. Игра должна быть видна на выбранном мониторе. Распознавание проверено на записи пользователя 1920×1080; управление пока не проверено в живом заезде. Первый запуск проводите под наблюдением.

## Запуск

`start.bat` запускает только полупрозрачную панель поверх игры: текущее действие и причина ожидания, W/E, счётчик завершённых заездов, передача, FPS анализа, состояние OCR и последнее действие. Основного окна и постоянно открытой консоли нет. Подробный журнал сохраняется в `bot.log`.

Клики проходят сквозь панель, она не забирает фокус игры. В эксклюзивном полноэкранном режиме Windows панель может быть скрыта игрой. **F8** — запуск/пауза, **F9** — пауза и сброс счётчика для новой серии, **F10** — выход с закрытием панели. **F6/F7** временно открывают снимок для калибровки; после неё остаётся только панель.

Включён **повторяющийся цикл по 45 заездов**. Лимит и упреждение переключения меняются в `config.json` перед запуском. STAGE не распознаётся и не влияет на решения.

Счётчик увеличивается только после последовательности «гонка → результаты CONTINUE → следующее меню NEXT STAGE/RACE». Повторные клики не увеличивают счётчик. Прогресс, состояние получения награды и число кругов сохраняются в `progress.json`. При автоматическом возврате счётчик сбрасывается только после подтверждённого стартового экрана; F9 для каждого круга не нужен. F9 позволяет вручную сбросить состояние и поставить бота на паузу.

1. Запустите `install.bat` (Python уже установлен в этой рабочей папке окружения). Затем `start.bat`.
2. Откройте Roblox на весь экран, выберите постоянное разрешение и масштаб интерфейса.
3. При интерфейсе как в записи ручная калибровка не нужна: профиль тахометра уже включён. Он рассчитан на 1920×1080 и масштабируется по высоте экрана; другие масштабы интерфейса нужно проверять отдельно.
4. Вернитесь в Roblox и нажмите **F8**. Повторное F8 ставит на паузу и отпускает клавиши. **F10** останавливает бота. При потере фокуса Roblox программа ставится на паузу; для продолжения снова F8.
5. Если готовый профиль не совпадает с вашей шкалой, покажите тахометр и нажмите **F6** перед стартом или **F7** в гонке. На замороженном снимке кликните в центр вращения стрелки, затем на внешний край окружности шкалы. Esc отменяет. Игра во время калибровки продолжает идти. Ручные координаты имеют приоритет над профилем записи.

Перед стартом распознаются белая, голубая и зелёная стрелка. На последней передаче синяя зона исчезает: надпись TOP GEAR распознаётся по шаблону из записи, и газ продолжает удерживаться до финиша. После изменения масштаба интерфейса может потребоваться F6/F7. Бот не записывает экран; небольшие вырезки для автоматических тестов находятся в `tests/fixtures`.

Для подтверждения тахометра проверяются серая ось стрелки, тёмный циферблат и красные отметки высоких оборотов. Голубые рамки персонажей и баннеры меню сами по себе не считаются тахометром. При сомнительном распознавании шкалы параллельно проверяются кнопки: найденное меню имеет приоритет, W отпускается.

Перед стартом цель — **голубая стрелка**. Её цвет отдельно отображается на панели. Газ подаётся короткими импульсами; контроллер учитывает скорость движения стрелки, оценивает её подъём/падение при W и отпускании и корректирует целевые обороты по наблюдаемому голубому цвету. Проверка на модели разгона не заменяет проверку реакции конкретной игры; стопроцентное попадание не гарантируется.

Для машины из записи настроено 9 передач (`max_gears` в config.json). Цифра текущей передачи распознаётся по шаблонам из видео: повторный E на той же передаче блокируется. После смены цифры выдерживается короткая пауза, а при падении оборотов E не нажимается. Для другой машины проверьте число передач и положение интерфейса.

## Поведение

- START / NEXT STAGE → клик.
- До 45 завершённых заездов → RACE / NEXT STAGE. После 45 → CASH OUT → COLLECT → повторный вход через E → новая серия с нулевым счётчиком.
- Перед стартом → импульсы W с обратной связью по движению и голубому цвету стрелки.
- Гонка → удержание W, импульс E при достижении синего сектора. Следующее переключение разрешается после падения оборотов.
- CONTINUE → клик и ожидание следующего меню.

Нужен полный экран меню с английскими надписями, как на примерах. Основной поиск распознаёт надписи внутри цветных кнопок по небольшим шаблонам из записи, включая наведение курсора. Он проверяет нижнюю часть экрана каждые 120 мс. Для клика нужны два последовательных совпадения, после нажатия выдерживается 300 мс перед дальнейшим поиском. Проверка кнопок на кадрах записи занимает несколько миллисекунд; это не полное время реакции с захватом, проверкой и самим нажатием.

Если визуальный поиск не нашёл подходящей кнопки, отдельный поток OCR читает нижнюю область экрана. При первом подтверждённом COLLECT его визуальный шаблон сохраняется для следующих кругов. После COLLECT бот ждёт 1 секунду для загрузки, затем автоматически удерживает E по 1,5 секунды с паузой в 1 секунду между попытками. Поиск и координаты подсказки для этого не нужны: машина может появиться с любой стороны входа. При подтверждении START E отпускается и счётчик обнуляется. F8/F10 и потеря фокуса игры отпускают E немедленно. OCR может при первом запуске скачать модели; ошибки записываются в `bot.log`.

## Настройки config.json

- `race_limit: 45` — предел завершённых заездов перед CASH OUT. Старое поле `cash_out_before_stage` используется только при переносе настроек, если `race_limit` отсутствует.
- `repeat_runs: true` — после CASH OUT получить награду и начать новую серию автоматически.
- `entry_initial_delay_seconds: 1.0` — задержка после COLLECT перед автоматическим удержанием E.
- `entry_hold_seconds: 1.5` — максимальная длительность одного удержания E у входа; START завершает удержание раньше.
- `entry_retry_seconds: 1.0` — пауза перед повторной попыткой входа.
- `target_fps: 120` — целевая частота анализа; фактическая зависит от захвата экрана и компьютера, отображается в логе. Это не гарантия frame-perfect.
- `shift_lead_ms: 12` — прогноз положения стрелки для компенсации задержки. При поздних переключениях немного увеличьте; при ранних уменьшите. Поправка требует настройки на вашей машине.
- `shift_cooldown_ms: 180` — минимальное время между переключениями.
- `monitor: 1` — индекс монитора MSS. После изменения повторите калибровку.

W/E отправляются через Windows SendInput (скан-коды). Бот проверяет, что активный процесс — RobloxPlayerBeta.exe; фоновый ввод не поддерживается. Игра и программа должны работать с одинаковыми правами. Возможность приема синтетического ввода нужно проверить в игре.

Для кнопок меню сначала отправляется относительное движение мыши, затем курсор уводится с кнопки и возвращается через [абсолютное событие мыши Windows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-mouseinput). После ещё одного небольшого относительного движения выдерживается 80 мс наведения и 100 мс удержания ЛКМ. Перед нажатием проверяются фокус и положение курсора. Журнал пишет координаты и факт отправки ЛКМ; это не подтверждение перехода самой игры. Если кнопка остаётся на экране, после повторного распознавания бот повторяет попытку.

## Проверка

`.venv\Scripts\python.exe -m unittest -v` — тесты круговой шкалы, счётчика завершённых заездов, сохранения прогресса, выбора CASH OUT и отправки мыши. Они не заменяют проверку на реальном UI.

Есть также тесты на реальных вырезках из записи: три цвета стрелки перед стартом, гонка, последняя передача и отбрасывание меню.

Тесты не отправляют ввод в игру. Они проверяют распознавание сохранённых вырезок, управление газом на модели, нажатия мыши, приоритет меню, сохранение прогресса и повторные циклы. Для тестов повторного входа используется сокращённый лимит 3, настройки рабочего бота при этом не меняются.

Использованы [MSS](https://python-mss.readthedocs.io/stable/examples.html) для захвата экрана и [RapidOCR](https://github.com/RapidAI/RapidOCR) для распознавания меню.
